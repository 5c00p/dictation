# ТЗ: Системная голосовая диктовка «VoiceType» (Speech-to-Text для любого приложения)

> Аналог расширения **Voice In — Speech-To-Text Dictation**, но работающий на уровне ОС, а не только в браузере. Цель — диктовать промпты в desktop-приложение Claude (и в любое другое окно с полем ввода) на русском и белорусском языках.

---

## 1. Назначение и контекст

Пользователь пишет большое количество промптов вручную. Desktop-приложение Claude и большинство нативных приложений Windows не имеют встроенной голосовой диктовки с поддержкой русского и белорусского языков.

Нужно standalone-приложение, которое:

1. Захватывает звук с микрофона по горячей клавише.
2. Транскрибирует речь в текст (RU + BE) на лету.
3. **Вставляет распознанный текст в то место, где сейчас находится курсор** — в активное поле ввода любого приложения (Claude, IDE, браузер, мессенджеры, 1С:EDT и т.д.).

Ключевое отличие от Voice In: работа на системном уровне через перехват фокуса ОС, а не внутри одной вкладки браузера.

---

## 2. Целевая платформа и ограничения

- **ОС:** Windows 10/11 (x64). Это приоритет №1.
- **Язык реализации:** Python 3.12, управление зависимостями через `uv` (как в существующих проектах).
- **Приватность:** контент промптов конфиденциален → по умолчанию **локальная** обработка без отправки в облако. Облачные провайдеры — опциональный режим.
- **Целевые приложения:** должно работать с Electron-приложениями (Claude Desktop, VS Code), Win32-приложениями, браузерами, 1С:EDT (Eclipse/SWT). Текст должен корректно вставляться кириллицей и латиницей (Unicode).

---

## 3. Функциональные требования

### 3.1 Режимы работы (оба обязательны)

| Режим | Поведение | Назначение |
|-------|-----------|------------|
| **Push-to-talk** | Удерживать горячую клавишу → говорить → отпустить → текст вставляется | Короткие фразы, точечная диктовка |
| **Toggle (диктовка)** | Нажать хоткей → старт → говорить непрерывно → текст вставляется чанками по паузам (VAD) → нажать хоткей → стоп | Длинные промпты «на лету» |

### 3.2 Распознавание речи

- Поддержка **русского** и **белорусского** языков.
- Режимы выбора языка:
  - Фиксированный язык (`ru` / `be`) — переключение хоткеем или из трея.
  - Автоопределение языка (Whisper language detection) — для смешанной RU/BE речи.
- **Кастомный словарь / bias** для специфичных терминов: названия продуктов doTERRA (DigestZen, TerraShield, PB Restore, Deep Blue и т.д.), технические термины (1С, FastAPI, asyncpg, Redmine, Nextcloud). Реализуется через `initial_prompt` в Whisper.
- Постобработка текста (опционально, настраивается):
  - Автоматическая капитализация первого слова.
  - Голосовые команды пунктуации: «точка», «запятая», «новая строка», «знак вопроса» → `.` `,` `\n` `?`.
  - Числа словами → цифрами (опционально, off по умолчанию).

### 3.3 Вставка текста (text injection)

- Текст вставляется в **активное поле ввода в позицию каретки**.
- **Основной метод:** вставка через буфер обмена (сохранить текущий буфер → положить распознанный текст → эмулировать `Ctrl+V` → восстановить буфер). Самый надёжный способ для Unicode/кириллицы и работает в Electron, браузерах, 1С:EDT.
- **Fallback-метод:** посимвольный ввод через `SendInput` с флагом `KEYEVENTF_UNICODE` (для полей, где paste заблокирован).
- Метод вставки выбирается в настройках; по умолчанию — clipboard-paste.

### 3.4 Управление

- Глобальные горячие клавиши (configurable), значения по умолчанию:
  - Push-to-talk: `Ctrl+Alt` (удержание).
  - Toggle-диктовка: `Ctrl+Alt+Space`.
  - Переключение языка RU/BE: `Ctrl+Alt+L`.
- Иконка в системном трее с меню: статус, выбор языка, выбор устройства ввода, открыть настройки, выход.
- Визуальная индикация состояния: цвет иконки трея (idle / запись / распознавание) + опциональный звуковой сигнал старт/стоп.

## 4. Нефункциональные требования

- **Задержка:** для push-to-talk время от отпускания клавиши до вставки текста ≤ 1.5 с на типичной фразе (10–15 слов) при работе на GPU; для toggle-режима чанки вставляются по паузам речи (VAD), задержка чанка ≤ 1 с.
- **Точность:** приоритет качества для белорусского → использовать модель не ниже `large-v3` или `whisper turbo`; для русского допустимы более лёгкие модели при нехватке ресурсов.
- **Ресурсы:** автодетект GPU (CUDA) с fallback на CPU (`int8`-квантизация для CPU).
- **Автозапуск:** опция запуска при старте Windows (ярлык в `shell:startup` или ключ реестра `Run`).
- **Логирование:** структурные логи (английский язык, как в остальных проектах), уровень настраивается; без логирования самого распознанного текста по умолчанию (приватность).
- **Стабильность:** приложение не должно падать при смене аудиоустройства, отключении микрофона, потере фокуса окна.

## 5. Предлагаемая архитектура

```
voicetype/
├─ src/voicetype/
│  ├─ __main__.py            # entry point, инициализация tray + hotkeys
│  ├─ config.py              # загрузка/валидация config.toml (pydantic)
│  ├─ hotkeys.py             # регистрация глобальных хоткеев
│  ├─ audio/
│  │  ├─ capture.py          # захват микрофона (sounddevice)
│  │  └─ vad.py              # детекция голосовой активности (silero-vad)
│  ├─ stt/
│  │  ├─ base.py             # абстрактный STTProvider (интерфейс)
│  │  ├─ local_whisper.py    # faster-whisper (локально)
│  │  └─ cloud/              # опциональные облачные провайдеры
│  │     ├─ openai_whisper.py
│  │     └─ yandex_speechkit.py
│  ├─ inject/
│  │  ├─ clipboard.py        # вставка через буфер обмена + Ctrl+V
│  │  └─ unicode_input.py    # fallback: SendInput KEYEVENTF_UNICODE
│  ├─ postprocess.py         # пунктуация, капитализация, команды
│  ├─ tray.py               # иконка трея, меню, индикация статуса
│  └─ controller.py         # оркестрация: hotkey → capture → stt → inject
├─ config.toml.example
├─ pyproject.toml            # uv-проект
└─ README.md
```

**Ключевая абстракция** — интерфейс `STTProvider` с методами `transcribe(audio) -> str` и `transcribe_stream(chunks) -> Iterator[str]`. Это позволяет менять движок (локальный/облачный) без переписывания остального кода — по аналогии с подходом `SendPulseProvider` в `social_inbox`.

## 6. Технологический стек (рекомендации с обоснованием)

| Компонент | Рекомендация | Обоснование |
|-----------|--------------|-------------|
| STT (локально) | **faster-whisper** (`large-v3` / `turbo`) | Уже используется в pipeline транскрипции встреч; поддерживает `ru` и `be`; CTranslate2 даёт скорость + int8 на CPU |
| Захват аудио | `sounddevice` | Простой PCM-стрим, выбор устройства, без C-зависимостей PyAudio |
| VAD | `silero-vad` | Точнее `webrtcvad`, нарезка по паузам для toggle-режима |
| Хоткеи | `pynput` или `keyboard` | Глобальный перехват; `pynput` стабильнее для удержания push-to-talk |
| Трей | `pystray` + `Pillow` | Кросс-платформенный systray, динамическая смена иконки |
| Вставка | `pyperclip` + `ctypes`/`pywin32` (`SendInput`) | Clipboard-paste как основной, Unicode SendInput как fallback |
| Конфиг | `pydantic` + `tomllib` | Валидация, дефолты, как в остальных проектах |
| Сборка | `PyInstaller` (one-file `.exe`) | Чтобы запускать без установки Python |

**Опциональные облачные провайдеры** (если потребуется минимальная задержка / стриминг и приватность не критична):
- **Yandex SpeechKit** — лучшее качество для русского, есть стриминг; уточнить наличие белорусского.
- **OpenAI Whisper API** — простой REST, `ru`/`be`, но без стриминга (только готовый аудиофрагмент).
- **Deepgram / AssemblyAI** — стриминг с низкой задержкой; проверить поддержку BE.

## 7. Детали реализации ключевых узлов

### 7.1 Вставка текста через буфер обмена (основной метод)

Псевдокод:

```
prev_clipboard = clipboard.get()        # сохранить, если возможно
clipboard.set(recognized_text)
sleep(0.05)                             # дать ОС обновить буфер
send_keys(Ctrl+V)
sleep(0.1)
clipboard.set(prev_clipboard)           # восстановить
```

Нюансы:
- Восстановление буфера делать с задержкой, иначе приложение успевает вставить старое значение.
- Если в буфере было нетекстовое содержимое (картинка) — либо не восстанавливать, либо логировать предупреждение.
- Для Electron/Claude paste работает нативно.

### 7.2 Unicode SendInput (fallback)

Использовать `INPUT` структуры с `KEYEVENTF_UNICODE` через `ctypes`, отправляя символы по кодовым точкам (включая суррогатные пары). Подходит для полей, где `Ctrl+V` перехватывается приложением.

### 7.3 Toggle-режим «на лету» (стриминг)

MVP-стратегия — **chunked transcription по VAD**, без настоящего стриминга:
1. Непрерывно читаем аудио в кольцевой буфер.
2. `silero-vad` детектирует конец фразы (пауза).
3. Сегмент отправляется в Whisper → результат вставляется.
4. Цикл продолжается до остановки хоткеем.

Это даёт ощущение «на лету» при простоте реализации. Истинный стриминг (`whisper_streaming` от UFAL или облачный стриминг-API) — задача следующей итерации.

### 7.4 Bias для терминологии

`faster-whisper` поддерживает `initial_prompt`. Передавать строку вида: список doTERRA-продуктов и технических терминов — это повышает корректность распознавания специфичных слов. Список вынести в `config.toml`.

## 8. Конфигурация (`config.toml`)

```toml
[stt]
provider = "local_whisper"     # local_whisper | openai | yandex
model = "large-v3"             # tiny|base|small|medium|large-v3|turbo
device = "auto"                # auto|cuda|cpu
compute_type = "auto"          # float16|int8|auto
default_language = "ru"        # ru|be|auto
initial_prompt = "doTERRA, DigestZen, TerraShield, PB Restore, FastAPI, asyncpg, Redmine, Nextcloud"

[hotkeys]
push_to_talk = "ctrl+alt"
toggle = "ctrl+alt+space"
switch_language = "ctrl+alt+l"

[audio]
input_device = ""              # пусто = устройство по умолчанию
sample_rate = 16000

[inject]
method = "clipboard"           # clipboard | unicode
restore_clipboard = true

[postprocess]
capitalize_first = true
voice_punctuation = true       # "точка" -> "."
numbers_to_digits = false

[app]
autostart = false
sound_feedback = true
log_level = "INFO"
log_transcripts = false        # приватность
```

## 9. Этапы разработки

**MVP (приоритет):**
1. Захват микрофона + push-to-talk по хоткею.
2. Локальная транскрипция через faster-whisper (`ru`).
3. Вставка текста через clipboard-paste.
4. Иконка трея со статусом и выходом.

**Итерация 2:**
5. Toggle-режим с VAD-чанками.
6. Поддержка белорусского + переключение/автоопределение языка.
7. Постобработка (пунктуация, капитализация).
8. Конфиг-файл + меню настроек в трее.

**Итерация 3:**
9. Fallback Unicode SendInput.
10. Опциональные облачные провайдеры (интерфейс уже готов).
11. Сборка `.exe` (PyInstaller) + автозапуск.

## 11. Критерии приёмки

- [ ] Удержание хоткея → диктовка → текст появляется в активном поле любого из тестовых приложений.
- [ ] Кириллица и латиница вставляются без искажений.
- [ ] Toggle-режим вставляет текст чанками по паузам без остановки записи.
- [ ] Переключение RU ↔ BE работает; автоопределение распознаёт оба языка.
- [ ] Буфер обмена пользователя восстанавливается после вставки.
- [ ] Приложение запускается из трея, не падает при типовых сбоях микрофона.
- [ ] Контент промптов не уходит в облако в режиме `local_whisper` и не пишется в логи при `log_transcripts = false`.

## 12. Открытые вопросы (уточнить до старта)

1. Есть ли на машине GPU с CUDA? От этого зависит выбор модели по умолчанию (`large-v3` на GPU vs `turbo`/`small int8` на CPU).
2. Нужна ли работа полностью офлайн, или допустим облачный режим для снижения задержки?
3. Качество распознавания белорусского у Whisper варьируется — приемлемо ли начать с `large-v3`, и при необходимости рассмотреть дообученные модели / облачный провайдер?
4. Нужен ли отдельный режим «вставлять без авто-пунктуации» (сырой текст) для кода/логов?
